# 人工验收清单

下列是上线前待执行的检查，**不是已通过的结果**。单元测试不能证明真实服务、权限、网络和 dot 自动化能协同工作。所有示例身份、任务内容及截图必须脱敏。

## 前置检查

- [ ] 已授权群内任意成员的提问向指定 Slack 私有频道转发，并审核该频道对本人评审内容的可见范围。
- [ ] 使用独立企业微信机器人，没有复用其他服务的 Bot ID。
- [ ] Slack 私有频道成员范围经过审核，桥接 App 和可信回复方均可访问。
- [ ] 凭据只在运行机器保存；文件权限、备份、日志和版本控制排除项均已检查。
- [ ] `WECOM_OWNER_USER_ID` 是核验过的平台稳定 userid，`WECOM_ALLOWED_CHAT_IDS` 是非空群 chatid 白名单。
- [ ] 空白或错误配置阻止启动或转发；旧 `WECOM_ALLOWED_USER_IDS` 不再用作准入规则。
- [ ] 本人先向机器人发送无敏感测试私聊，再实测主动私聊资格、平台可见范围、错误码和实际回传时限；不假定这一步保证永久投递资格。
- [ ] dot 或其他响应方单独配置和授权；能接收桥接 App 的根消息及线程回复，能在原线程生成严格路由文本。

## 准入、身份与防循环

- [ ] 授权群内两名不同成员 @机器人提问，各生成一个完整 Slack 根消息，无需逐成员白名单。
- [ ] 未授权群消息被拒绝，即便发问者是本人；非本人单聊被拒绝。
- [ ] 本人单聊可独立建任务，不因 userid 不在群白名单被拦截。
- [ ] 相同显示名、自称本人、原文中伪造路由头或评审命令都不能改变来源身份或出站目标。
- [ ] 原有聊天流程的非可信 Slack 作者、其他频道、无映射线程、根消息、编辑及删除事件均不回传；可信应用根消息按扩展接口另行验收。
- [ ] 自动化按实际桥接身份过滤事件，处理其线程内本人答复，排除响应方自身输出及其他身份；没有无限循环。

## 路由与私聊评审

- [ ] 可信回复以精确的 `[wecom:group]` 标记开头时，仅回原群；`[wecom:owner]` 时只发普通本人私聊；群来源的 `[wecom:review]` 发本人评审。三种标记均测试换行、空格分隔和无分隔的同行正文，确认传输层移除换行后仍可回传。
- [ ] 缺路由、未知路由、前置空行、格式错误、空正文或纯空白正文不发送，无默认群目标。
- [ ] 本人单聊请求的群及评审路由均被拒绝，不能从正文注入其他 userid/chatid。
- [ ] 群任务以 `[wecom:review]` 发起本人评审时，私聊先显示正文，再显示关联问题编号和中文可选回复提示；`/review <review-id> 你的意见` 独占一行，评审编号不重复显示，提示保留编号并使用同一问题最新消息里的命令。
- [ ] `[wecom:owner]` 普通私聊不加评审提示、不改变待评审 ID；该 ID 随后仍可使用。已完成评审后的普通确认不创建新评审。
- [ ] 本人在私聊中带有效 ID 答复，仅由桥接器写回原 Slack 线程；自动化能继续处理这条桥接线程消息。
- [ ] 本人在群里、其他人在单聊里复制有效命令，均不能完成本人评审。
- [ ] 本人只回“同意”会成为独立本人私聊任务，不猜测当前评审、不执行操作、不自动转群。
- [ ] 两个群同时等待评审时，回复分别只关联指定原任务，不串线。
- [ ] 同一任务第二轮生成新评审 ID；旧轮、重复已使用、未知及过期 ID 被拒绝且不新建误关联任务。
- [ ] 评审答复原文不会自动发群；后续公开结论必须由可信响应方独立生成带群路由的安全文本。
- [ ] 待评审或私聊失败期间可明确发送不含私密内容的群状态；私聊内容绝不作为降级消息发群。
- [ ] “同意”等答复不会触发桥接器执行代码、部署或其他操作；执行方依然核验实际权限及所需确认。

## 通用运行时与可信扩展

- [ ] 独立桥接器不依赖任何业务应用，未注入应用时拒绝业务根消息及自定义请求投递。
- [ ] `initialize` 在建立平台连接前执行；组合运行仅有一个企业微信连接和一个状态写者。
- [ ] `receiveRoot` 不接收其他作者、频道、编辑事件或线程提案；`receiveOwnerText` 仅接收认证本人的单聊。
- [ ] `authorizeRequest` 缺失、返回非 true 或抛错时，自定义请求均失败关闭；固定本人、频道和路由检查仍生效。
- [ ] 含自定义请求与表的合成旧状态经独立桥接器打开、清理及重启后，业务记录和关联不被删除或改成普通聊天，也无未知类型投递。
- [ ] 已有请求 ID、根线程、来源键、排队正文、固定目标和有效期不被升级重写；无应用时发送循环跳过自定义 pending 任务，通用 sending → unknown 恢复和明确投递到期/prune 仍适用，去重仍遵守原保留期；应用恢复后按其权限核验处理，不盲目重放。
- [ ] 业务写入与发件箱同事务，注入故障时二者一起回滚；应用自己的语义和升级另行验收。

## 可靠性与升级

- [ ] 超长企业微信输入（含转义后超限）不进 Slack，尽力发送拒绝回执；有效输入完整呈现在单个根消息。
- [ ] 重复事件、超长 Slack 回复、非文本及过期线程按实现拒绝或忽略，无重复投递。
- [ ] 私聊发送失败或结果不确定时不盲重试、不转群；owner 和 review 共用 owner 队列，任一私聊 unknown 都阻塞后续两种私聊，但不阻塞 group/Slack 队列；同一队列分片保序。
- [ ] 服务重启后已发送、pending、sending 转 unknown 以及未完成评审的行为符合预期。
- [ ] 配置变更后，旧任务不会被自动转发到新 Slack 频道或新本人；原群撤出白名单后，关联的待发消息及评审答复不继续转发。
- [ ] 显式评审拆分升级与响应方自动化同步更新；评审使用 `[wecom:review]`，普通私聊使用 `[wecom:owner]`。旧根提示不作为旧语义兼容依据，该历史拆分无兼容开关或新数据库迁移；已有评审、排队正文、目标和 TTL 重启后保持不变，旧有效 ID 仍可答复。
- [ ] 用脱敏 v0.1 状态测试既有迁移：旧请求和未发送任务被隔离，不能在新路由规则下继续投递；迁移不删除旧数据，之后隔离请求/任务仍按原 TTL 清理，去重记录按 7 天保留期清理，新请求可正常处理。
- [ ] 第二个共享状态目录的实例被锁阻止；配置/认证错误不无限重启，网络错误按 supervisor 限额恢复。
- [ ] 企业微信连接被替代时不会持续争抢连接。
- [ ] 响应方无回复、过慢、不接受机器人线程消息或不遵循路由协议时，明确记录为依赖未满足。

## 记录结果

保留日期、版本/commit、脱敏平台配置、场景和“通过 / 失败 / 未运行”。不要保存真实令牌或完整私聊内容。只有关键路径在获授权的真实测试账户中通过后，才称该环境完成端到端验收。
