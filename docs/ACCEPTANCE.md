# 人工验收清单

下列均为上线前需要执行的检查，不是已通过的结果。仅单元测试不能证明真实服务、权限、网络和 dot 自动化能协同工作。

## 前置检查

- [ ] 已明确授权双向转发的人员、内容类别、目的地和回复身份。
- [ ] 使用新的独立企业微信机器人；没有复用 Hermes 或其他服务正在使用的 Bot ID。
- [ ] Slack 是专用私有频道，成员范围经过审核；桥接 App 已加入频道。
- [ ] 凭据仅保存在运行机器上；权限、文件模式、备份和日志已检查。
- [ ] 白名单和回复身份使用实际稳定 ID；空白/错误配置会阻止启动或转发。
- [ ] dot 在该账户可用，能够接收此频道的机器人消息并在线程内回复；独立自动化已配置且获得授权。

## 功能与安全场景

- [ ] 允许成员发送无敏感内容的唯一测试文本：Slack 仅出现一个根消息。
- [ ] 指定身份在该线程回复：文本只回传原企业微信会话。
- [ ] 两名允许成员同时发问：两个线程的回复不会串到另一会话。
- [ ] 未授权成员的消息不会出现在 Slack。
- [ ] 其他 Slack 人员、机器人和相同显示名的伪装身份无法回传。
- [ ] 其他频道、无映射线程、根消息、编辑/删除事件不会被误回传。
- [ ] 桥接器自身消息不会触发无限循环；dot 的触发规则不会响应自身回复。
- [ ] 超长企业微信输入（包括转义后超限）不进入 Slack；尽力发送明确拒绝回执。允许输入完整呈现在一个根消息，不依赖分片到齐触发。
- [ ] 重复事件、超长 Slack 回复、非文本消息及过期线程按当前实现安全处理。
- [ ] Slack 发送失败、企业微信发送失败或网络中断时，没有把“可能已发送”误报为未发送后无限重发。
- [ ] 验证服务停止/重启后的未完成消息行为，并向使用者说明可能需要重新发问。
- [ ] 第二个使用同一状态目录的实例被锁阻止；配置/认证错误不会无限重启，网络失败按 supervisor 限额恢复。
- [ ] 验证企业微信机器人被替代连接挤下线时不会持续争抢连接。
- [ ] dot 无回复、回复过慢或不处理机器人消息时，能识别为依赖未满足，而非桥接器已完成全流程。

## 记录结果

保留日期、版本/commit、平台配置、脱敏场景和“通过 / 失败 / 未运行”。不要保存真实令牌或完整私聊内容。只有上述关键路径在授权测试账户中实际验证后，才称该环境完成端到端验收。
