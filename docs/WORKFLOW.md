# Issue 工作流与执行边界

本文区分已实现能力与后续接入约定。**设计获批不等于自动执行已启用。** 桥接器继续只负责消息传输和决定留档，不负责扫描、领单、执行或部署。

## 当前支持与待接入能力

- 已支持：按配置与身份限制转发文本；另行启用的 Issue 快照评审；按指定版本持久记录 `approve/reject/defer`。记录带 `decision_record_only: true`，不能作为执行授权。
- 已另行授权的独立自动化：每小时发现新增 Issue，供线索接入与本人评审使用；这不是开发执行扫描，也不赋予领单或执行权限。
- 已实现并有单元测试：`src/workflow-control.js` 独立控制基础模块，默认 `executionReady: false`，提供模式、版本化授权、额度门槛和单任务占用检查；模块未接入在线工作流，不会自行执行任务。
- 尚未接入：10 分钟开发任务扫描器、执行器、真实额度与数据时效适配器、跨参与者共享领单适配器，以及实际生效的自动模式控制入口。
- 因此，目前不能声称已经开启自动开发扫描、可靠读取额度、实现跨机器互斥或支持下述自然语言控制命令。单元测试通过也不代表这些端到端能力可用。

基础模块使用单独的 SQLite 数据库；占用互斥仅覆盖访问同一数据库的调用者。每个 Issue 版本最多一份执行授权，可通过 `revokeGrant` 撤销；`authorizeStep` 要求每个实际操作前检查停止状态、额度、有效期及撤销状态。当前只接受 `edit-code`、`run-tests`、`open-draft-pr` 三类操作，不含 push、merge 或 deploy，也没有执行这些操作的适配器。`scope` 只是范围描述，不是文件沙箱；未来执行适配器必须强制校验仓库和文件路径范围，并验证真实操作者身份与额度来源。

## 三类入口，一个正式台账

1. 企业微信反馈：保留原始来源与必要上下文，按获准范围整理成待处理的 GitHub 反馈；不自动转为正式仓库台账中的已受理任务。
2. 人工 GitHub Issue：以仓库中的实际 Issue、评论和相关记录为准。
3. 未来 AI 发现：仅为拟议入口，**AI 巡检尚未启用**；来源标记为 `ai` 不代表已经运行巡检，也不赋予执行权限。

入口只决定线索来源。任何来源都不能跳过本人审阅、版本绑定和执行授权。桥接快照及聊天摘要不是正式仓库状态的替代品；不得因采用新流程而批量改写旧 Issue 状态、补造批准或关闭历史问题。发现差异时保留证据并核对台账。

## 四件事必须分开记录

1. **受理**：确认问题值得跟踪，记录问题、范围及来源；不表示实施方案已获批准。
2. **实施方案批准**：本人认可指定版本的方案与验收条件；不自动开始执行。现有 `approve/reject/defer` 仍仅是决定记录，不能被升级解释为执行许可。
3. **执行授权**：独立、不可变、带版本的授权记录，明确绑定 Issue、方案版本、授权人、执行范围与有效期。修订须生成新版本并明确旧版本失效关系，不覆盖旧记录；执行前核验当前有效版本，缺失、过期、撤销或内容不匹配时停止。独立记录不意味着强制重复确认：未来入口支持后，本人一次明确批准指定版本、范围及执行意图，可以同时形成方案批准与执行授权，无需对同一动作再问一次。当前 `decision_record_only` 记录仍不能承担这一用途。
4. **执行结果**：记录实际变更、测试证据、未完成项及相关提交或 PR；失败、暂停、完成均如实区分。完成代码不等于已验收或已部署。

部署是单独阶段，必须独立明确授权及目标环境，不能由受理、方案批准、执行授权或代码完成推导。任何自动模式都不放宽权限和确认要求。

## 拟议运行模式

默认是**手动模式**：不后台扫描开发任务、不自行领单；不影响另行授权的每小时线索发现与评审流程。本人明确点名某个 Issue 并给出有效执行授权后，才可派发该任务；只讨论问题或批准方案不能触发派发。

自动模式必须由本人明确开启，并有确定的起止时间，例如开启三天；基础模块限制每次窗口最长七天。启用期间拟每 10 分钟检查一次，最多运行一个任务；每次领单都须重新核验有效授权、共享占用状态、剩余额度及其时效。模块只检查扫描间隔，没有定时器。开启自动模式不等于批准所有 Issue。

- 剩余额度 **≤5%**，或额度未知、读取失败、数据过期：禁止新任务，不把“读不到”当作额度充足。
- 到期或收到停止指令：立即关闭后续扫描与领单；正在执行的任务默认到安全检查点后暂停并记录现场，不能继续整单直到完成。
- 只有本人明确要求“做完当前任务”时，才在既有授权范围内完成当前任务；仍禁止领新任务。
- 有效自动窗口内队列为空时，保持等待；后续轮询可领取新出现且满足所有门槛的任务，这不是重新开启模式。
- 停止、到期或额度触发暂停后，不能因额度恢复或收到新 Issue 自行重新开启；恢复须本人重新明确开启并设定期限。自动窗口绑定控制器实例，重启后也必须明确调用 `startAuto` 重新开启；遗留占用须先人工核验，不能直接重领。

### 额度接入方案与限制

按 [Codex App Server 官方额度接口说明](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)，先调用 `account/rateLimits/read` 读取快照，再处理 `account/rateLimits/updated` 通知。适配器须检查 `primary`、`secondary` 的 `usedPercent`，并处理 `rateLimitsByLimitId` 多额度桶，不能只挑剩余额度最多的一项。

接入前核验目标机器的已安装版本、实际登录账户，以及当前任务适用的额度桶和时间窗口。对所有适用窗口按 `100 - usedPercent` 计算剩余百分比；无法确定适用范围、必要字段缺失或数据过期时禁止新任务。派发前立即重新读取，执行中在安全检查点复核，不能仅依赖每 10 分钟的扫描快照。

目前只核对过云端 CLI 的协议 schema，**Mac 上的实际额度接入尚未验证**，真实适配器仍待实现。额度读取不是原子预留：同账户其他会话的并发消耗、通知延迟和当前步骤消耗都可能使余额越过阈值。5% 是禁止启动新任务的检查门槛，不保证账户始终精确保留 5%。

## 共享领单要求

共享领单必须覆盖自动执行器、人工派发，以及本人直接在本地 Codex 开工的情况。所有参与者都须在同一权威机制中检查并原子认领，明确任务与执行者、有效授权版本、占用时效、续期及安全释放规则；失效或冲突时禁止另开重复任务，先核验现有执行现场。

**适配器尚未接入前，不具备跨机器锁或全局互斥保证。** 本地状态或进程锁不能代替共享领单。接入前保持人工协调，不启用无人值守自动领单。

## 本人指令示例（未来约定，当前不生效）

以下只是待实现的交互语义，不是现有机器人命令；模糊的“同意”也不能替代明确的对象、版本与授权范围。

- “执行 Issue #123，按方案第 2 版”：核验并记录独立执行授权后，仅派发该 Issue。
- “开启自动模式三天”：确认明确的起止时间，只处理已获有效执行授权的任务。
- “停止自动模式”：立即停扫描、停领单；当前任务到安全检查点暂停。
- “停止自动模式，做完当前任务”：停扫描、停领单，只完成当前已授权任务。
- “恢复自动模式一天”：重新建立有期限的开启记录，不沿用过期窗口。

## 启用自动模式前的验收门槛

- 接入可核验本人身份的控制入口，以及不可变、版本化执行授权的存储与核验。
- 接入正式仓库台账、10 分钟扫描调度、单任务执行器和真实额度适配器；明确额度单位、最大数据年龄和读取失败行为。
- 让自动执行器和本地 Codex 等所有参与者接入共享领单，验证同时认领、续期失败、崩溃恢复与重复派发均安全。
- 实测停止、到期、安全检查点、明确做完当前任务及禁止自动恢复；验证额度恰为 5%、未知和过期时均不启动新任务。
- 验证决定记录不能执行、旧授权不能复用、部署需独立授权；保留验收证据后再宣布相应能力可用。

公开文档、样例及验收证据只用虚构或脱敏信息，不包含私有仓库、用户、频道、主机标识或任何凭据。
