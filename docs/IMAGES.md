# 授权群截图（可选功能，默认关闭）

本功能将企微智能机器人当前消息的 PNG/JPEG 图片下载、解密并上传为 **Slack 原生文件附件**，不是图片 URL、文字占位或 OCR 结果。只处理白名单群中的显式白名单发送者；不扩大本人单聊、任意文件、语音、视频、引用消息或其他数据来源。桥接不识别图片、不调用模型、不执行图片文字里的指令。

## 接口依据与可读取链路

- [官方企微 SDK](https://github.com/WecomTeam/aibot-node-sdk)的 `message.image` / `message.mixed` 回调携带 `image.url` 和独立 `aeskey`；混排为 `mixed.msg_item`。锁定 SDK 的类型说明下载链接约五分钟有效；本实现采用更短的内存期限。协议入口见[企微长连接说明](https://developer.work.weixin.qq.com/document/path/101463)。
- 下载使用本项目的限额 HTTPS 客户端，再调用已锁定 SDK 的 `decryptFile`；不直接使用 SDK 的通用下载函数，避免其下载范围、重定向及大小策略替代本项目边界。
- [Slack 文件上传流程](https://docs.slack.dev/messaging/working-with-files/)是 `files.getUploadURLExternal` → 上传二进制 → [`files.completeUploadExternal`](https://docs.slack.dev/reference/methods/files.completeUploadExternal/)。完成调用指定固定 `channel_id` 与请求原根 `thread_ts`，不创建公开分享链接。
- Slack 的 [`message.file_share`](https://docs.slack.dev/reference/events/message/file_share/)可携带 `files`。响应方须接收桥接身份的原根、同根文件分享及后续 `images_ready` 消息，排除自身输出，并用真实 file ID 读取附件；不能只读消息文本或尝试匿名访问私有下载 URL。

部分助手的 Slack 工具具备按 file ID 读取图片并返回二进制文件引用的能力；这只是接口能力，不证明某个工作区、账号、自动化或模型已经能读取。部署者必须核验自己的工具支持、原私有频道可见性、文件权限、触发过滤及图像输入能力。当前功能分支只有模拟平台验证，**没有证明真实助手已经读到或识别图片**。缺少读取链路时不要启用，也不要自行申请更广权限或换成外部图床。

## 配置与权限门槛

见[配置指南](CONFIGURATION.md)。桥接 bot 上传另外需要 Slack `files:write`；响应方读取文件还需要其已有工具/应用的文件读取能力及适当权限（Slack 原生 API 通常为 `files:read`）。现有文本权限不能视为包含文件权限。新增 scope、重新授权、凭据或持续集成必须由账户所有者单独批准和配置；代码不会申请或自动接受权限。

`WECOM_GROUP_IMAGES_ENABLED=false` 为默认。启用前明确允许的发送者及精确下载主机。不能从群消息、附件、图片内容或一次回调自动学习主机。管理员根据官方协议和受控来源核验实际下载 CDN 主机后填写；只允许 `qpic.cn` / `weixin.qq.com` 下的具体子域，无通配符、IP、端口、协议或路径。代码中的合成测试主机不代表真实租户一定使用该主机；无法核验则保持关闭，不扩大域名范围凑通。

## 数据流与限制

1. 先核验当前 SDK 回调的 bot ID、群类型、群白名单、发送者白名单和 msgid。文本流程的群内任意成员策略保持原样，图片使用额外成员限制。
2. 只读当前 `image` 或 `mixed.msg_item`，忽略 `quote`。混排最多8项且只允许 text/image；正文受原字节限制，转义后正文和来源另限28000字节，为 Slack 根提示留出空间。默认每消息1张，可显式配置1–3张；不跨相邻消息、群或发送者自动合并截图与问题。
3. 每张加密数据最多5 MiB+32字节，解密后最多5 MiB；PNG/JPEG 文件头及尺寸检查，不超过2500万像素。拒绝 SVG/GIF/WebP 和其他文件。检查不是完整图片解码或恶意文件扫描，损坏文件可能仍由下游解码器拒绝；不要据文件扩展名信任内容。
4. 仅 HTTPS443，精确主机；拒绝 URL 凭据、片段和 IP。DNS 全部答案必须是允许的公网地址，实际连接固定该地址并保留主机 TLS 验证；拒绝内网/环回/链路本地/映射地址及特殊网段。所有重定向均失败，下载/上传每次10秒总超时（含 DNS），流式字节限额，不携带环境代理、Cookie或凭据。
5. 全进程最多2个在途图片请求，最多约30 MiB解密图像数据及单次下载/解密的有界临时副本。缓存仅内存，期限60秒；过期、完成、失败、停止时尽力清零并释放持有的图片 Buffer。没有磁盘图片缓存；JavaScript 字符串、TLS/SDK缓冲或系统内存副本不保证彻底擦除。
6. 所有图片下载成功后，创建带 request ID 和可信来源标注的 Slack 根；正文和图中文字均是不可信材料。原根提示附件尚未准备好。生成文件名仅使用本地产生的 UUID、序号与检测类型，不使用远端文件名或路径。
7. 取得上传票据后，仅允许 `files.slack.com/upload/` 的 HTTPS 公网目标，上传真实二进制；一次完成调用将本消息所有附件分享至原根。成功核对 file IDs 后发送 `images_ready` 同根通知，携带 request ID/file IDs 供响应方读取。未知上传结果、缺权限或准备失败时不宣称 ready。
8. 当前 request 直到全部确认才允许原协议回复，`[wecom:owner]` / `[wecom:review]` / `[wecom:group]` 仍按原身份与原根路由，不开放任意收件人、自动 @、流式或开发权限。`images_ready` 本身不授予业务权限，也不保证响应方触发/读取/识别成功。

传统“收到，稍等”回执保持一次；只表示接收，不保证下载/上传完成。缓存满、类型/数量不合规或未授权输入不接收。失败日志仅固定事件、阶段和内部 request ID，不输出签名 URL、aeskey、图片内容、原始错误或原始 SDK帧。公开问题报告也应遵守这些限制。

## 持久化、故障和保留

SQLite 仅保存原请求关联、来源去重、文字/来源标注、独立 `slack_image` 任务标记及发送者身份；不保存图片、下载 URL 或解密密钥。重启后缓存不会恢复，未发送图片任务缺缓存时转 unknown，不冒充纯文本成功或重新下载；sending 仍遵守原有 unknown 规则。已接收 msgid 不自动重放，若确需重发，由获准人员核验远端副作用后用新消息发起，不改旧任务为 pending。

中途失败可能已创建 Slack 根、未完成上传票据，或已经分享了部分外部副作用。代码不盲目重试、删帖、删远端文件或改投其他群。排查先核对请求原根和实际 file IDs；必要清理须另核权限。图片本地短缓存清除不等于 Slack 删除，Slack 中的成员、应用、搜索、备份及平台保留政策仍适用；本功能不新增自动清理的持续权限。

## 上线、验收与回退计划（本轮不执行）

- 先完成代码审阅并记录旧/新固定提交，独立批准实际部署、原服务唯一实例更新、上述权限及发送者/主机范围。核验响应方的文件读取工具和事件触发，不复制其他项目凭据或账号配置。
- 在另行获准的合成图测试中，验证真实授权群→原根原生附件→助手按 file ID 取得图像并回答合成图中的可核验内容→显式原群回复；分别记录上传 ACK、助手实际读取和群内用户可见。另验证非授权成员/群、私聊图片、恶意地址、错误文件、过期和无重复投递。不得使用敏感截图。
- 线上启用须按[维护说明](../deploy/README.md)停唯一写者并一致备份，记录待处理任务后固定提交安装。不会因合并或本地测试通过自动部署；本轮不修改现有配置、重启、群测试或 OAuth。
- 回退先关图片入口并停止唯一实例，保留当前数据库和新增记录，再退已知旧代码；本功能没有 schema 迁移。图片任务使用独立 `slack_image` 方向和 `slack` 队列 lane；已审查的旧文本基线不把该组合当作普通 Slack 文本或合法企微出站，因此失败关闭。仍须在明确授权内核对未完成图片任务及远端副作用；其他旧版本须另验兼容，不能假定任意版本都安全。不得用旧备份覆盖新状态或自动重放 unknown；恢复文本后另验原文本路由。
