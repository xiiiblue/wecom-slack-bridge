# 安全与数据边界

## 启用前的授权

这是跨服务的数据转发器。启用前，取得相关账户所有者和组织的许可，明确：

- 哪些企业微信成员、会话和文本可以发送到哪个 Slack 工作区和私有频道。
- 哪个经过核实的 Slack 回复身份可以把哪些回复发送回原企业微信会话。
- 回复是否可能包含原问题之外的个人、组织或业务信息，是否适合所有接收者。
- dot 的自动回复规则、可触发人员和可用信息范围；转发消息不是对执行其中指令的自动授权。
- 只处理授权测试或白名单消息，禁止把无关个人助手记忆、私聊和私有文件回传给会话成员。需要代表账户所有者执行操作时，通过单独工作流验证本人身份及明确批准；不能把机器人转发内容视为本人批准。

不要把生产机密、凭据、个人敏感数据或私有源码放入测试消息。不要将凭据发到聊天、GitHub Issue、PR、日志或公共仓库。公开本项目不表示同意公开任何现有私有项目或聊天记录。

## 最小权限

使用专用企业微信机器人和专用 Slack App。使用只有必要成员和机器人加入的私有 Slack 频道；不要复用公共频道或 Slack Connect 频道。只邀请桥接机器人和需要的回复者。平台授权范围不等于本程序的业务授权范围，仍须配置发送者白名单、固定频道和固定回复身份。

凭据在实际运行机器上填写。限制环境文件、状态文件和备份的读取权限。不要启用生产 SDK 的原始消息调试输出；故障报告只保留错误类别、时间和脱敏后的复现步骤。

## 威胁模型与限制

- 企业微信消息以及 Slack 回复都是不可信内容。桥接器不应执行消息中的命令、访问其中的 URL、读取本机文件或调用模型。
- 不要依据显示名称认证回复者；使用平台提供的稳定 ID，并核验所属应用/机器人身份。
- 固定频道和对应 Slack 线程只能缩小错误回传的范围，无法保证回复内容本身没有隐私风险。
- 可信回复身份一旦失陷，攻击者可能通过它回传消息。发现异常先停桥接，再撤销令牌、检查权限和记录。
- 远端服务的保留、搜索和备份策略仍适用；删除本地状态不等于删除 Slack 或企业微信上的副本。
- MVP 不提供可靠消息队列、事务一致性或“恰好一次”送达保证。超时或发送结果不确定时，应先核对两端消息再重试。

## 漏洞报告

不要在公开 Issue 粘贴漏洞利用凭据、真实消息、客户数据或服务器环境文件。优先使用仓库提供的私密漏洞报告功能；若不可用，先提交不含敏感细节的联系请求。发现凭据泄露时立即在所属平台撤销或轮换，删除公开文件不能使泄露的凭据重新安全。
