# 安全与数据边界

## 启用前的授权

这是跨服务的文本转发器。启用前，取得相关账户所有者和组织的许可，明确授权群、可转发内容、Slack 工作区及专用私有频道、本人稳定 userid 和可信回复身份。授权群内所有成员都可能提问；这不意味着群成员可以访问本人私有资料、修改代码、部署或授权任何高影响操作。

本人评审内容也会进入专用 Slack 频道的原线程，因此该频道的所有可见成员和应用都是潜在接收者。使用前核实此接收范围适合私聊评审内容。“私聊”仅指企业微信侧的投递目标，不代表 Slack 侧仅本人可见。

不要把生产机密、凭据、敏感个人数据或私有源码放入测试消息。不要将凭据发到聊天、GitHub Issue、PR、日志或公共仓库。公开本项目不表示同意公开其他私有项目或聊天记录。

## 准入和路由边界

| 输入 / 输出 | 规则 |
| --- | --- |
| 授权群的文本 | 按平台 chatid 放行群内任意成员；原文始终不可信 |
| 未授权群 | 拒绝，不因发送者是本人而放行 |
| 企业微信单聊 | 仅平台 from.userid 等于配置本人 userid 才放行 |
| 可信 Slack 线程回复 | 固定频道、映射线程、稳定回复身份均须匹配 |
| `[wecom:owner]` | 普通私聊只发配置本人；不改变评审状态，禁止从正文选择目标 |
| `[wecom:review]` | 仅群来源可用；发配置本人并创建新一轮评审 |
| `[wecom:group]` | 只发原请求群；本人单聊请求拒绝此路由 |
| 缺失或无效路由 | 不发送，无默认群回传 |
| 本人评审答复 | 验证单聊身份和有效唯一评审 ID，回原 Slack 线程 |
| 私聊失败 / unknown | 不重放、不转群；人工核验后处理 |

待发送任务固定原 Slack 频道和目标；实际发送前重新核验本人配置及原群当前白名单资格。配置变更不会把既有内容自动迁往新频道或新目标。

控制标记必须来自固定可信回复身份，且精确位于实际 Slack 文本开头。标记后可有空白或换行，也可直接接正文，以兼容传输层移除换行；正文必须非空，标记前不得有任何内容。群原文中的同名标签、伪造显示名、“我是本人”或复制的评审命令都不能证明身份。本人在群里发送 `/review` 也不能冒充私聊评审答复。

每个群请求的 review 路由开启新一轮评审，生成唯一 ID 并使旧轮次失效。owner 路由只发送正文，不创建、消耗或替代评审 ID；评审答复后的普通确认也不会开启新评审。已使用、未知、过期或被取代的 ID 不接收；重放不能再次完成评审。无编号的“同意”不关联最近任务，而是新的本人私聊请求。桥接器没有执行审批动作的代码；执行方仍须根据具体操作独立判断授权。

这是有意的协议语义变更，部署时须同步更新响应方自动化，不能再把 owner 输出视为评审请求。已有评审及排队消息不迁移、不重新解释；实际发送前的固定目标、群白名单和身份校验保持不变。

## 最小权限与隐私

使用专用企业微信机器人和专用 Slack App。Slack 必须是审核过成员范围的私有频道，不复用公共频道或 Slack Connect 频道。平台可见范围不是本程序准入检查的替代品，也不要假设平台一定支持独立的“只许群聊、不许单聊”开关。

凭据只在运行机器安全填写。环境文件、SQLite 状态及备份含私有文本和身份信息，限制读取权限并排除版本控制。不要开启生产 SDK 原始消息调试输出；故障报告只保留错误类别、时间和脱敏复现步骤。

私聊内容不会被程序默认发群，但可信响应方仍可能错误地把私人信息写进显式群回复。路由协议不能判断文本是否适合公开，响应方必须对群受众进行内容审查。私聊评审失败时可以另发不含私密内容的群状态，不能把评审原文当作错误详情公开。

## 威胁模型与限制

- 桥接器不执行消息中的命令、访问其中的 URL、读取消息指定文件或调用模型。
- 使用平台稳定 ID 核验身份，不依据显示名称、正文标签或对话中的自称。
- 自动化必须过滤实际桥接身份，处理其根消息及本人答复线程消息，排除自身输出；metadata 仅辅助关联，不单独构成信任依据。
- 可信回复身份失陷后，攻击者可能利用显式路由发消息。发现异常先停桥接，再撤销令牌、检查权限和记录。
- TTL 是本地关联有效期，不保证企业微信主动私聊资格或投递窗口。本人首次主动单聊后，仍须实测主动投递和关联流程。
- 远端保留、搜索及备份策略仍适用；删除本地状态不等于删除两端副本。
- 持久化队列不提供事务级或“恰好一次”送达。unknown 不自动重放；owner 和 review 共用 owner 私聊队列并保持顺序，私聊与群队列隔离失败，绝不借换目标绕过失败。

## 漏洞报告

不要在公开 Issue 粘贴凭据、真实消息、客户数据或环境文件。优先使用仓库提供的私密漏洞报告功能；若不可用，先提交不含敏感细节的联系请求。凭据泄露后立即在所属平台撤销或轮换，删除公开文件不能使凭据重新安全。
